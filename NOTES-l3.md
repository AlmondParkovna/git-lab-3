## 1. stash list рядок із вашим -m

Команди:

``` bash
git stash push -u -m "чернетка ліцензії v5"
git stash list
```

Зафіксований рядок виводу:

``` text
stash@{0}: On lab3/variant-5-Buy: чернетка ліцензії v5
```

Параметр `-m` задає повідомлення stash, а `-u` додає до stash також
невідстежувані файли. Після перевірки stash було відновлено командою
`git stash pop`, тому запис більше не зберігається у поточному списку.

## 2. cherry-pick два хеші і чому вони різні

``` text
97b0cb8 Уточнити ліцензію
f295292 Уточнити ліцензію
```

Перший коміт створено у гілці `feature/pick-5`, а другий --- у
результаті `git cherry-pick` у гілці `lab3/variant-5-Buy`. Хеші різні,
бо cherry-pick створює новий коміт із тим самим змістом змін, але з
іншим батьківським комітом та власними метаданими.

## 3. reflog два рядки до і після amend

Фрагмент `git reflog -5`:

``` text
d9aa452 HEAD@{...}: commit (amend): Зафіксувати ліцензію, варіант 5
f295292 HEAD@{...}: cherry-pick: Уточнити ліцензію
```

`git commit --amend -m "Зафіксувати ліцензію, варіант 5"` замінив
попередній коміт `f295292` новим комітом `d9aa452`. Старий запис
залишився в reflog, що дозволяє побачити попередній стан гілки.

## 4. revert log --oneline, видно обидва коміти

``` text
7311c79 Revert "Зіпсувати рядок"
de6c97d Зіпсувати рядок
d9aa452 Зафіксувати ліцензію, варіант 5
```

Спочатку коміт `de6c97d` додав помилковий рядок
`ЛІЦЕНЗІЯ: усі права скасовано`. Команда `git revert HEAD` створила
окремий коміт `7311c79`, який скасував ці зміни, не переписуючи
опубліковану історію.

## 5. тег фрагмент git show: tag, Tagger, повідомлення

Команда: `git show v0.1-Buy`

``` text
tag v0.1-Buy
Tagger: Владислав Буй <topgoodnice@gmail.com>
Перший зріз варіанта 5
```

Створено анотований тег `v0.1-Buy` з повідомленням
`Перший зріз варіанта 5` і відправлено його на `origin`. Тег позначає
коміт `7311c79` --- результат скасування помилкового рядка.

## 6. rebase -i pick / squash і підсумкове повідомлення

Команда: `git rebase -i HEAD~2`

``` text
pick 425b3e7 WIP: чернетка
squash 01619b6 fix typo
```

Підсумковий коміт після успішного об'єднання:

``` text
c9cbba5 Уточнити ліцензію
```

Коміт `fix typo` було об'єднано з попереднім комітом `WIP: чернетка`
через `squash`, а підсумкове повідомлення встановлено як
`Уточнити ліцензію`. Після завершення rebase зміни успішно відправлено
командою `git push --force-with-lease origin lab3/variant-5-Buy`.

## 7. blame один рядок

Команда: `git blame -L 1,5 LICENSE.md`

``` text
d9aa452d (Владислав Буй 2026-10-13 21:55:21 +0300 1) Ліцензія: MIT-NC навчальна (lab3-v5)
d9aa452d (Владислав Буй 2026-10-13 21:55:21 +0300 2) Ліцензія: MIT-NC навчальна (lab3-v5)
7311c799 (Владислав Буй 2026-10-13 22:04:46 +0300 3) Уточнення варіанта 5
```

`git blame` показує коміт, автора та час останньої зміни кожного рядка.
У цьому файлі перші два рядки походять із коміту `d9aa452`, а третій ---
із `7311c79`.

## 8. fork origin, upstream, куди push і куди PR

-   `origin` --- мій власний репозиторій:
    https://github.com/AlmondParkovna/git-lab-3
-   Робоча гілка для push: `lab3/variant-5-Buy`
-   `upstream` --- оригінальний репозиторій, з якого зроблено fork (у
    цій роботі додатковий remote не налаштовувався).
-   Зміни надсилаються через `git push` до `origin`.
-   Pull Request створюється з моєї гілки в `origin` до відповідної
    гілки оригінального репозиторію (`upstream`), зазвичай `main`, якщо
    це вимагає власник проєкту.

Команда push після інтерактивного rebase:

``` bash
git push --force-with-lease origin lab3/variant-5-Buy
```

``` text
7311c79..c9cbba5  lab3/variant-5-Buy -> lab3/variant-5-Buy
```
